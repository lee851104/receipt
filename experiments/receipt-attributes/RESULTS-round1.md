# 本機模型實測結果

完成日期：2026-10-12。結論：三個候選模型已下載並完成同條件測試；本輪沒有可直接接入正式程式的模型。1.5B 整筆初稿一致數較多，3B 抓到少數酒精屬性，但兩者都有明顯漏判。若保留後續實驗基準，保留 1.5B；這不是部署建議。

## 資料與實測條件

- 使用實際存在的 0301-0331.csv 原樣副本，35 筆明細、25 個不同品名、28 組店家／品名／數量組合。原始檔沒有更動。
- 全部使用官方 Qwen2.5 Instruct GGUF Q4_K_M，未訓練或微調。下載版本及 SHA256 見 runtime/download-manifest.json。
- llama.cpp b11557 Windows CPU x64；CPU 2 threads、IDLE priority、GPU off；模型依序執行，沒有呼叫雲端推論。
- 三者共用 prompt-named-v2.txt、temperature=0、seed=42、context=4096、batch size=3。耗時含模型載入，為本機單次測量，不代表一般硬體效能。
- 本輪用此份資料修過提示，因此是開發集，不是獨立測試集。參考答案是助理初稿，使用者尚未複核。

## 同條件結果

「整筆一致」要求 16 個屬性與 7 個基本旗標全部符合初稿；分母均為 28，失敗批次算未完成。

| 模型 | 格式有效組數 | 整筆符合初稿 | 布林屬性正例命中 | 耗時 |
| --- | ---: | ---: | ---: | ---: |
| Qwen2.5 0.5B | 25/28 | 0/28 | 0/8 | 169.4 秒 |
| Qwen2.5 1.5B | 28/28 | 9/28 | 0/8 | 287.7 秒 |
| Qwen2.5 3B | 28/28 | 6/28 | 2/8 | 351.3 秒 |

以上是與初稿的一致程度，不是經人工驗證的準確率。大量欄位為 false，不能用總欄位一致率宣稱模型表現良好。

- 0.5B：一批 yes/unknown 出現矛盾或重複標籤，整批 3 組被拒絕。沒有產生完整逐列標註。
- 1.5B：格式完整，但漏掉全部大量購買、下廚及酒精正例；也把部分熟食判成下廚食材。
- 3B：酒精命中 2/3，但大量購買 0/4、下廚 0/1；仍有熟食判成飲料或生鮮的情況。
- 1.5B 與 3B 都產生 35 筆 annotated-rows.json，代表能正確對回來源列，不代表判斷正確，也不代表已整合正式訊號計算。

逐欄比較、私人品名與原始回應都留在被 Git 排除的 results/，公開文件不複製這些品名。

## 未覆蓋與待確認

初稿的布林屬性正例只有 cooking 1 組、bulk 4 組、alcohol 3 組。sugar 有 1 組非空值，但商品解讀仍待使用者確認。其餘 12 個屬性沒有正例，無法評估辨識能力。印花與加價項目也有解讀歧義，詳見 private/draft-reference.json 的 notes。

private/human-review.json 保留空白供人工複核，目前狀態 NOT_REVIEWED。這輪結果不能回答「16 個屬性是否都能可靠辨識」，也不能證明較大模型必然更好。

## 初輪及失敗紀錄

最初的位置陣列提示保存在 prompt-array-v1.txt；0.5B 完成但大多回 null，1.5B 試跑後中止。舊結果在 results/archive/，舊執行器在 private/run_models-array-v1.py。

同一個 1.5B 的簡單具名欄位診斷能輸出有效布林值；也檢查過執行器支援 boolean/null 與 tuple schema。因此改用具名 yes/unknown 清單重跑全部模型。位置陣列較難對準欄位只是可能原因，不能據此斷言根因。最終表格只納入同一份具名提示的完整輪次。

總執行器 exit code 1 來自 0.5B 的驗證失敗；1.5B、3B 仍依序跑完，沒有隱藏失敗或以初稿補答案。
