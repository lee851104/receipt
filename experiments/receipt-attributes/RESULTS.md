# 最終模型選型與四項指標

決定：選 Qwen3-4B-Instruct-2507 Q4_K_M，搭配固定大量購買規則與甜度文字驗證，作為離線、待複核的輔助標註方案。主程式尚未整合，不能自動把模型結果當已確認分類。

Qwen3 在涵蓋 16 個屬性的補充集上，純模型 Macro F1 最高；但純模型在真實資料的 F1 只有 44.44%，比 Qwen2.5 3B 的 50.00% 還低。不能省略這個落差：Qwen3 多次擅自猜測未明示甜度，規則驗證是所選方案不可省略的一部分。

## 資料與證據層級

- 真實集：0301-0331.csv 原樣副本，35 筆明細、28 組店家／品名／數量。屬性只有 9 個正標籤，涵蓋 4 個屬性，其餘 12 個缺正例。參考答案是助理初稿，尚未經使用者確認。
- 補充集：54 筆合成診斷情境，864 個欄位、45 個正標籤，每屬性有 2–6 個正例。推論前凍結，另由未看輸出的審查者檢查標籤。不是獨立真實測試集。
- 三月資料曾用於提示調整。甜度 guard 又是在看過本輪錯誤後新增，因此最終方案數字是修正後開發資料回測，不能當作泛化準確率或獨立 holdout 成績。原始模型與 bulk-only 結果全部保留。
- 四模型同用 prompt-named-v2、temperature=0、seed=42、batch=3、context=4096、CPU 2 threads／IDLE priority，GPU off；無候選模型雲端推論。新 4B 的原模型來自 Qwen，實際 GGUF 為 bartowski 轉換版，已固定 revision 與 SHA256。

## 選定方案：Qwen3 4B 加規則與驗證（事後回測）

大量購買：數量 >=3 或明確多入／整箱／家庭號等證據才補 true；其他欄位不改。甜度：品名沒有明確甜度詞，就把模型猜出的數字清為 null。兩者不讀標準答案、不補失敗項目，原始預測不覆寫；同樣的規則也套用其他模型並另列於 metrics.csv。

開發回測達到事先設定的數值門檻（兩集 micro F1 >=90%、補充集 macro F1 >=85%），但這不是部署核准。尚缺人工確認的獨立真實測試集，production_ready 保持 false。

真實資料仍漏掉 1 個下廚屬性；16 屬性整筆一致 27/28。接入原程式另需的 7 個 basic 旗標，其 F1 為 85.39%，生鮮辨識尤其不足，因此不能宣稱完整原程式流水線已驗證。

## 速度、失敗與重現

Qwen3 補充集耗時 1251.0 秒（約 20.9 分鐘）；三月 28 組耗時 646.0 秒（約 10.8 分鐘）。包含載入，為低優先序且有其他工作並行的單次本機時間，不是穩定效能基準。適合先離線標註、人工複核，再讓介面讀檔。
 
0.5B 補充集有 3 批、真實集有 1 批格式驗證失敗，均保留於分母。其他三模型兩組資料都完成且無格式失敗。執行中的舊 wrapper 曾忽略失敗 exit code，已修正並測試；本輪以儲存的 failures 與完整 ID 覆蓋驗證完成，不以 exit code 當唯一證據。

所有 raw、bulk-only、policy-guards 四項指標：results/followup/comparison.json、metrics.csv。逐批回答、差異與規則改動也保留在 results/，全部由 Git 排除。完整計分方式見 METRICS.md；Accuracy 是欄位準確率，P/R/F1 採正標籤 micro，不能只看大量負例撐高的 Accuracy。
