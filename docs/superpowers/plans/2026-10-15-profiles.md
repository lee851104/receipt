# 品味向量（角色 1 第 2 週，第二批）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 上傳的背景工作在最後用這個人所有月份的品項重算 18 格品味向量，存進 `profiles`；`GET /api/me/profile` 讓使用者看到自己的品味和月報。屬性一律來自 `item_cache` 裡的模型結果（design D6），待分析的品項只在需要屬性的格子裡當成沒有資料。

**Architecture:** `src/receipt/` 加一條「模型屬性」的路：`attributes.from_model` 把 23 個欄位換成 `describe` 的同一組答案，`signals.gather`／`measure` 和 `traits.explain` 多一個 `attributes` 參數（不給時 v1 照舊，現有測試不改）。`src/api/profiles.py` 從 `items` 和 `item_cache` 組出月份資料、算出向量和生活圈，用 upsert 存進 `profiles`；`jobs.process` 在判斷完屬性之後呼叫它（已經在 `WORK` 鎖裡）。`src/api/routes/me.py` 提供 `GET /api/me/profile`。

**Spec:** `docs/team/overview.md` 5.4 第 3 步、5.6；design D3、D4、D6；OpenSpec taste-profile、item-attributes 規格；tasks 2.4（最後一步）、2.5。

## 決定（2026-10-15，角色 1）

1. **模型屬性怎麼換成訊號用的答案**（`attributes.from_model(row, channel, fields, vocabulary)`，回傳和 `describe` 同樣的 17 個鍵）：
   - 類別的門檻照舊：`food` 看類別；`clearance` 只看食物、`quick` 只看正餐、`cooking` 只看生鮮、`kitchen` 只看生鮮和日用品、`sport_gear`／`car_care`／`home`／`stationery` 只看非食物。不在門檻內是 `False`（不適用），在門檻內就用模型的值，`None` 保持 `None`
   - `sugar`：只有飲品有；模型給 `None` 時套用現有的甜度預設規則（`sugar_of`，taste-profile 規格「飲品的甜度預設值」）
   - `bulk`：數量 ≥ 3 一定是 `True`（數量是發票上的事實，模型看不到），否則用模型的值
   - `fun`：模型的 movie／singing／show／game 換成 電影／唱歌／展演／遊樂；模型沒有給時，看店家名稱有沒有娛樂的字（和 `channel_of` 一樣是店家的規則，不看品名）
   - `species`：只接受 `cat`、`dog`，其他當 `None`
   - 整個品名還在待分析（`fields is None`）時，除了 `food`、`sugar` 的預設規則和店家的 `fun`，全部是 `None`
2. **`None` 是沒有資料，不是「沒有」**：比例型的訊號（`clearance_share`、`store_clearance_share`、`fresh_share`、`bulk_share`）分母只算那個屬性已知的品項；計次型的訊號（例如 `alcohol_items`）本來就只數 `True`。v1 的規則從來不給 `None`（甜度除外，已經另外處理），所以 v1 的結果不變。
3. **7 個基本旗標**（food、meal、drink、fresh、daily、tech、sport）先不用：類別仍然來自分類模型。
4. **`profiles`**：每次工作的最後重算一次，`vector` 存 JSON（`allow_nan=False`），資料不足時是 `null`；`item_count` 是有效品項數；`areas` 是 `places.areas_of` 的結果。用 `INSERT … ON CONFLICT(user_id) DO UPDATE`。重算失敗和其他失敗一樣讓工作變成 failed，舊的 profile 保持原樣。
5. **`pending_attributes`**：這個人所有品項裡，`item_cache` 沒有（以目前的屬性模型）的不重複品名數。
6. 假用戶的品項和 profile 由 seed 擴充時放入（D10，之後的任務）；在那之前假用戶查 `GET /api/me/profile` 是 `ready: false`。

## Task 1：模型屬性接進品味計算（`src/receipt/`）

**Files:** `src/receipt/attributes.py`、`src/receipt/signals.py`、`src/receipt/traits.py`；新測試 `tests/test_model_attributes.py`

- `attributes.py`：`FUN_WORDS = {"movie": "電影", "singing": "唱歌", "show": "展演", "game": "遊樂"}`；`from_model(row, channel, fields, vocabulary)` 照「決定 1」
- `signals.py`：`gather(rows, context, attributes=None)`：`attributes` 是 `{品名: 23 個欄位或 None}`，給了就用 `from_model(row, channel, attributes.get(row["name"]), vocabulary)`，否則照舊用 `describe`；`measure(rows, period, context, attributes=None)` 傳下去；四個比例訊號的分母照「決定 2」改成只算已知的品項
- `traits.py`：`explain(rows, period, context, attributes=None)`、`build_vector(...)` 傳下去
- 測試：每一條換算規則（門檻、甜度預設、數量 ≥ 3、fun 換成中文和店家的 fun、species、待分析全部 `None`）；待分析的食物不算進 `clearance_share` 的分母；同一份虛構資料，`attributes` 給「和規則同樣答案的欄位」時向量和 v1 一樣；現有測試全部照樣通過
- Commit：`feat: let the taste pipeline read model attributes, where unknown means no data`

## Task 2：工作的最後重算 profile（`src/api/`）

**Files:** 新 `src/api/profiles.py`；`src/api/jobs.py`、`src/api/app.py`（`app.state.context = load_context(ROOT)`）、`src/api/routes/invoices.py`（把 context 交給 `run_job`）；測試 `tests/test_api_profiles.py`

- `profiles.months_of(items)`：`{"2026-05": {"year", "monthNumber", "month", "days", "rows": [...]}}`，`rows` 的欄位和 `build_month` 一樣（day、invoice、merchant、district、name、quantity、amount、category，加上 `provisional: False`），依日期排序
- `profiles.attributes_of(session, backends, names)`：只讀 `item_cache`（目前的屬性模型），不問模型
- `profiles.recompute(session, backends, context, user_id)`：讀這個人所有月份的 `items` → `months_of` → `traits.dated` → `explain(..., attributes)`；`item_count` 用 `measure` 的 `counts["items"]`（沒有任何品項時是 0）；`areas` 用 `places.areas_of`；upsert 進 `profiles`
- `jobs.process`：判斷完屬性之後 `update(message="重算品味向量")`，`recompute`，最後才 `status="done"`（re-upload 只刪已結束的工作，所以 done 必須是最後一次寫入）
- 測試：上傳後有 profile（3 筆虛構品項 → `item_count` 3、`vector` 為 `null`、`areas`）；25 筆以上的虛構月份 → 18 格；兩個月合併；重傳同一月份會重算；重算時出錯 → 工作 failed、舊 profile 不變；`vector` 裡沒有 NaN
- Commit：`feat: recompute a user's taste profile at the end of each upload job`
