Reading the status column

- covered: every behaviour the scenario's THEN states is asserted by at least one test (possibly split across a few tests). Unit-level proof of the deciding function counts when the HTTP wrapper is generic and tested elsewhere; the note says so.
- partial: a stated behaviour is not asserted anywhere; the note names it.
- none: no test found.

Where the cover lives (matters for CI)

- CI runs `python -m unittest discover -s tests` (requirements.txt only, so torch-based tests are skipped) and `node --test "tests/*.test.cjs"`.
- Not run by CI: the Playwright scripts `tests/web-v2-*-browser.cjs` and `tests/web-v2-live-browser.cjs` (driven by hand, the live one through `tests/run_web_v2_live.py`), the Docker acceptance scripts, and everything under `experiments/`.
- Covered only by a test outside tests/: model-evaluation 檢查切分 (covered), 產生比較表 and 稀少類別 (partial), all in `experiments/category-models/test_*.py`.
- Web scenarios whose only cover is a manual Playwright script: 更新與清理月報, 專注配對結果 (covered); 使用設定選單, 章節式轉場, 動態文字雲 (partial).
- Spec versus code (not a test gap): the two-month CSV error shows the English API message ('Expected one month per CSV') after '發票檔案格式不符。'; the spec and web test use the Chinese wording 一份檔案只能有一個月.
