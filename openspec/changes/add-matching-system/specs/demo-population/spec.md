# Spec Delta

## Purpose

在沒有真實用戶的情況下，提供約 300 位假用戶，讓配對清單有足夠的對象，也讓配對驗證有可以檢查的答案。

## ADDED Requirements

### Requirement: 約 300 位假用戶
系統 SHALL 提供約 300 位假用戶，平均分布在 8 種消費類型（省錢上班族、忙碌工程師、咖啡上班族、手搖學生、健身族、家庭下廚、連假旅人、質感貓奴），每位都有所屬類型，假發票上也有店家地址，可以推算常去行政區。

#### Scenario: 匯入假用戶
- **WHEN** 把假用戶匯入一個全新的資料庫
- **THEN** 資料庫有約 300 位假用戶，8 種類型的人數相差不超過 1 人

### Requirement: 走完整條管線產生
每位假用戶的品味向量 SHALL 由假發票經過與真人相同的管線產生（解析、分類、屬性、品味向量），MUST NOT 直接寫入隨機向量。

#### Scenario: 追溯一位假用戶
- **WHEN** 檢查任一位假用戶
- **THEN** 這位使用者有對應的假品項紀錄，而且用這些品項重新計算，會得到相同的品味向量

### Requirement: 可以重現
用同一個隨機種子產生假用戶時，結果 SHALL 完全相同。

#### Scenario: 重新產生
- **WHEN** 用同一個種子產生兩次假用戶
- **THEN** 兩次的姓名、類型、品項和品味向量都一模一樣

### Requirement: 假資料與真資料分開
假用戶和假品名 SHALL 標示為假資料，可以放進 git；假資料 MUST NOT 混入任何真實發票的內容。

#### Scenario: 檢查假資料檔案
- **WHEN** 檢查放進 git 的假資料檔案
- **THEN** 每一筆都標示為假資料，而且找不到任何真實品名或店家

### Requirement: 假用戶只能用 demo 方式登入
假用戶 SHALL 沒有可用的密碼，只能透過 demo 快速切換使用。

#### Scenario: 用密碼登入假用戶
- **WHEN** 有人嘗試用任何密碼登入一位假用戶
- **THEN** 系統回應 401
