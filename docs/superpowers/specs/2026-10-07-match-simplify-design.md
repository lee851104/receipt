# 配對頁簡化與分數統一：設計規格

- 日期：2026-10-07
- 分支：`feature/tags-matching`
- 依據：使用者回饋「介面太複雜」，以及外部審查的四點意見（地區影響排序、多人消費、混合葷素品名、隱私說明範圍）
- 前一份規格：[`2026-10-07-tags-matching-design.md`](2026-10-07-tags-matching-design.md)。本文件取代它的下列內容，其餘照舊：
  - 第 2 節的「可能多人的發票」、「消費檔次」與「葷素紀錄」的判斷順序
  - 第 3 節中常消費地區的相似度、「分數」、「候選名單與推薦門檻」、「配對理由」、「差異說明」
  - 第 5 節「配對頁」與嵌入資料格式
  - 第 6 節設定檔中的 `price_levels`、`weights`、`thresholds`

## 目標

配對頁只做一件事：列出最合拍的人，每人只帶兩個標籤，點進去看你和他的連線圖。分數只有一個，清單、門檻和連線圖都用同一個數字。地區不再參與分數，只在沒有人達到 80% 時，由使用者主動選擇範圍才使用。

## 已確認的決策

| 項目 | 決定 |
|---|---|
| 配對分數 | 品類、品牌、葷素紀錄、消費檔次依 35：15：10：10 加權，不含地區；清單數字、門檻、排序都用它 |
| 推薦門檻 | 80% 以上直接推薦；沒有人到 80% 時才出現距離選項，範圍內 70% 以上推薦 |
| 距離範圍 | 同一區／同縣市／同地區／不限，依行政區層級判斷，不用座標 |
| 清單 | 每人顯示名稱、配對分數、最像你、最不像你；兩個標籤都取自對方自己的標籤 |
| 連線圖 | 點卡片打開品味連線圖的配對模式：左邊你、右邊對方；大字是配對分數，小字是消費類型相似度 |
| 朋友比較 | 仍只比較 10 類消費筆數；計數規則改成同一張發票的同一品項只算一次；名稱統一為「消費類型相似度」 |
| 消費檔次 | 改為估算每人每餐花費：小資型 100 元以下、均衡型 100–299 元、享受型 300 元以上 |
| 葷素紀錄 | 肉類詞緊接在「素、素食、蔬食、植物」後面算仿肉；名稱有素食標記又另外加肉時為未知（已完成，`67e1ccf`） |
| 隱私說明 | 限定為「此配對頁」；私人版另外提醒整份報告含交易明細（已完成，`50e4b60`） |
| 報告動畫 | 三段各 6 秒，共 18 秒 |

## 1. 配對分數（`matching.py`）

- 品類、品牌、葷素紀錄、消費檔次的相似度算法不變；移除常消費地區的相似度與總分。
- `configs/tags.json` 的 `weights` 改為 `{"category": 0.35, "brand": 0.15, "flavor": 0.1, "price": 0.1}`。缺資料的面向不計分，權重依比例分給其他面向（同前）。
- 可比較條件不變：品類必須可比較，且品牌、葷素紀錄、消費檔次至少一項兩人都有。
- 分數以 0.5 進位的整數百分比顯示與比較。
- 候選名單：可比較、配對分數至少 70% 的虛構用戶，依配對分數由高到低排序，同分依名稱。
- `thresholds` 改為 `{"match": 0.8, "nearby": 0.7}`。

### 距離

- 縣市取行政區字串的前 3 個字（22 個縣市名稱都是 3 個字）。
- 地區分組寫在 `configs/tags.json` 的 `regions`：
  - 北部：臺北市、新北市、基隆市、桃園市、新竹市、新竹縣、宜蘭縣
  - 中部：苗栗縣、臺中市、彰化縣、南投縣、雲林縣
  - 南部：嘉義市、嘉義縣、臺南市、高雄市、屏東縣
  - 東部：花蓮縣、臺東縣
  - 離島：澎湖縣、金門縣、連江縣
- 兩個行政區的距離：相同為 0，同縣市為 1，同地區為 2，其他為 3。
- 我和對方的距離，取「我的常消費地區 × 對方的常消費地區」所有組合中的最小值；任一方沒有常消費地區時為 3。
- 虛構用戶的常消費地區只用來算距離，不放進網頁。

### 最像你、最不像你

- 比較對象是對方的標籤，但常消費地區不列入，因為推測的地區不當成配對理由。每個標籤用一個鍵判斷是否和我相同：品類偏好看分類，常去品牌看品牌，消費檔次看級距名稱，葷素紀錄看標籤文字。
- **最像你**：依「常去品牌 → 葷素紀錄 → 消費檔次 → 品類偏好」的順序，取對方第一個和我相同的標籤；同一面向內依對方的標籤順序。
- **最不像你**：依「葷素紀錄 → 消費檔次 → 常去品牌 → 品類偏好」的順序，取對方第一個和我不同的標籤。我在葷素紀錄或消費檔次沒有資料時，對方在該面向的標籤不列入。
- 找不到時，該行不顯示。
- 示範資料的結果：

| 對象 | 最像你 | 最不像你 |
|---|---|---|
| 手搖學生 A | 常去品牌：示範餐坊（21 次） | 常去品牌：示範水餃館（4 次） |
| 手搖學生 D | 常去品牌：示範茶屋（21 次） | 葷素紀錄：葷食品項較多 |
| 健身族 A | 常去品牌：示範餐坊（18 次） | 葷素紀錄：葷食品項較多 |

### 候選人輸出

```python
{
  "name": "手搖學生 D",
  "score": 81,                                    # 配對分數，整數百分比
  "distance": 0,                                  # 0 同一區、1 同縣市、2 同地區、3 其他
  "like": {"dimension": "常去品牌", "text": "示範茶屋（21 次）"},     # 找不到時為 None
  "unlike": {"dimension": "葷素紀錄", "text": "葷食品項較多"},       # 找不到時為 None
  "counts": [int] * 10,                           # 10 類有效品項筆數，給連線圖用
}
```

原本的 `total`、`taste`、`areas`、`tags`、`basis`、`reasons`、`differences` 移除。

## 2. 消費檔次（`tags.py`）

- 只看含正餐的發票，也就是該張發票有正金額、分類已確認的正餐列。
- 估計人數＝該張發票正餐列的數量加總。
- 每人花費＝該張發票中分類為正餐、飲品、零食甜點且分類已確認的列，金額加總（含折扣）÷ 估計人數。結果不大於 0 的發票不列入。
- 取每人花費的中位數，依 `price_levels` 分級：`[{"label": "小資型", "below": 100}, {"label": "均衡型", "below": 300}, {"label": "享受型"}]`。
- 餐飲發票少於 `min_records`（3 張）時不產生。
- 分類寫在設定 `"meal": {"portion_category": "正餐", "food_categories": ["正餐", "飲品", "零食甜點"]}`，依報告的分類名稱對應。
- 移除「可能多人的發票」規則；品牌與常消費地區仍依全部正金額發票計算。
- 例子：四人各點一鍋（420、380、450、350 元）加四杯飲料（共 200 元），算成 4 人份，每人 450 元，為享受型。

## 3. 配對頁（`match.html`、`match-filter.js`）

由上而下：

1. 「← 返回消費洞察」、標題、「配對對象是 40 位虛構示範用戶。」
2. 狀態與清單，依情況擇一：
   - 有人 80% 以上：「N 位配對分數 80% 以上」，列出前 5 位；超過 5 位時加上「顯示前 5 位」。
   - 沒有人 80% 以上，但有人 70% 以上：顯示「目前沒有 80% 以上的人。放寬到 70%，要找多遠？」，並說明「以你的常消費地區為準：高雄市苓雅區、高雄市新興區」。下方是「同一區、同縣市、同地區、不限」四個單選項，分別對應距離上限 0、1、2、3，預設都不選，每項標出人數（例如「同縣市 · 2 位」），人數為 0 的選項停用。選了之後列出範圍內的前 5 位。
   - 推測不出我的常消費地區時，只有「不限」可選，並說明原因。
   - 70% 以上一位都沒有：「目前沒有夠相似的人，多掃幾張發票再看看。」
   - 我的資料不足（`me.ready` 為假）：沿用原本的資料不足說明。
3. 卡片：名稱、配對分數、「最像你」「最不像你」兩行。距離模式另外標出距離（同一區、同縣市、同地區、其他地區）。整張卡片是按鈕，點了打開連線圖。
4. 兩個預設收合的區塊：「你的消費標籤」與「怎麼算的」。

- 顯示文字一律用 `textContent` 或 DOM 節點寫入。距離選擇不儲存。
- `match-filter.js` 提供 `recommend(candidates, maxDistance, thresholds)`：有人達到 `match` 門檻時，只回傳這些人並忽略距離；否則 `maxDistance` 為 `null` 時回傳空陣列；否則回傳配對分數達到 `nearby` 門檻、且 `distance` 不超過 `maxDistance` 的人。回傳結果保留原本排序。
- 「怎麼算的」說明：權重比、可比較條件、門檻與距離規則、消費檔次的估法與限制、同一張發票的同一品項只算一次，以及隱私說明（限定此配對頁；私人版提醒整份報告含交易明細）。

## 4. 連線圖的配對模式

- 報告新增 `<section id="connection-view">` 與 `<iframe id="connection-frame">`，載入和朋友比較相同的 `taste-page-source`。
- 路由為 `#connection`。配對頁點卡片時呼叫 `ReceiptPages.showConnection(pair)`，報告記下這組資料後切到 `#connection`；沒有資料時（例如重新整理頁面）改回 `#match`。每次打開都重新載入 iframe，避免狀態殘留。
- 朋友比較頁在 `connection-frame` 中執行時：
  - 開頁時向報告取得配對資料，左右固定為你和對方，不顯示匯入區。
  - 左側標示「你」，右側標示對方名稱與「配對對象」。
  - 大字標題為「配對分數」，數字和清單相同；下方小字為「消費類型相似度 N%（下圖）」。
  - 返回連結為「← 返回配對清單」，回到 `#match`，清單保留原本的距離選擇與捲動位置。
  - 連線、篩選與「臭味相投／背道而馳」照分類模式運作。
- 配對資料格式，兩側都要通過 `TasteProfile` 的驗證：

```python
{
  "score": 81,
  "left": {"name": "你", "demo": True, "months": ["2026-03", "2026-04"], "counts": [int] * 10},
  "right": {"name": "手搖學生 D", "demo": True, "months": ["2026-03", "2026-04"], "counts": [int] * 10},
}
```

## 5. 朋友比較頁（一般模式）

- `taste-profile.js` 的 `fromReport` 改成同一張發票的同一品名只算一次，和 `tags.py` 一致；沒有發票代碼的列各算一次。
- 說明文字「每筆正金額的品項算一次」改為「同一張發票的同一品項只算一次」；報告頁匯出面板的說明同步修改。
- 品味連結格式不變（`receipt-taste/categories-v1`）。匯出功能尚未開放，沒有已分享的連結會受影響。

## 6. 報告動畫（`insights-ui.js`）

- 每段 6 秒（日期推進 5 秒、停留 1 秒），三段共 18 秒；時間軸上限為 18，時間顯示「00:xx / 00:18」。
- 「直接看本章結果」與章節按鈕跳到的位置跟著調整；速度鈕 1×／1.5×／2× 不變。

## 7. 嵌入資料格式

```python

  "isDemo": True,
  "population": 40,
  "settings": {
    "weights": {"category": 0.35, "brand": 0.15, "flavor": 0.1, "price": 0.1},
    "thresholds": {"match": 0.8, "nearby": 0.7},
    "price_levels": [{"label": "小資型", "below": 100}, {"label": "均衡型", "below": 300}, {"label": "享受型"}],
    "top_matches": 5,
    "category_min_items": 10,

  "me": {
    "ready": True, "item_count": 97, "months": ["2026-03", "2026-04"],
    "areas": ["高雄市苓雅區", "高雄市新興區"],
    "tags": [{"dimension": "消費檔次", "text": "均衡型"}],
    "counts": [int] * 10,

  "candidates": [...],                             # 第 1 節的候選人輸出

```

- `me.ready` 為假時，`candidates` 為空陣列。
- 不放虛構用戶的常消費地區、完整標籤或明細。

## 8. 測試計畫

Python（`unittest`，全部使用虛構資料）：

- `matching`：同區與異區的配對分數相同；70% 下限與排序；距離 0–3，以及沒有地區時為 3；最像你與最不像你的順序、「不同」的判斷、我缺資料時略過；輸出欄位。
- `tags`：每人每餐花費（火鍋例子為享受型、飲料與折扣計入、沒有正餐的發票不列入、少於 3 張時不產生）。
- `personas`：每人最接近同類型（用配對分數）；同類型全部 80% 以上；3C 玩家不是候選人；示範的「我」至少 1 位 80% 以上、至少 1 位 70%–79%；手搖學生 D 的最不像你是「葷素紀錄：葷食品項較多」。
- 產生報告：嵌入資料格式；私人版資料不足時 `ready` 為假；候選人資料沒有常消費地區欄位；連線圖畫面與 template 存在。

Node（`node:test`）：

- `match-filter`：有人 80% 以上時忽略距離；沒有人 80% 以上時，未選距離回傳空陣列；選了距離回傳範圍內 70% 以上的人；保留排序。
- `taste-profile`：同一張發票的同一品名只算一次；沒有發票代碼時每列各算一次；配對資料的驗證。
- 現有測試全部通過。

瀏覽器檢查：清單只有兩個標籤；點卡片打開連線圖，分數和清單一致；返回後保留清單狀態；朋友比較頁不受影響；動畫 18 秒播完；手機寬度沒有水平捲動。

## 9. 校準（新規則模擬）

- 每位虛構用戶最接近的都是同類型；同類型 160 組全部 80% 以上；不同類型 1,400 組沒有任何一組達到 80%。
- 示範的「我」：手搖學生 80%–96%、健身族 71%–75%，其他類型都在 58% 以下。示範版因此一開始就有 5 位推薦，不會出現距離選項。
- 真實資料（只算數量）：0 位 80% 以上，4 位 70%–79%；同一區 0 位、同縣市 0 位、同地區 4 位、不限 4 位。

## 10. 不在這次範圍

- 示範版切換到「沒有人 80%」的畫面。
- 用座標計算實際距離。
- 增加消費分類（「10 類」仍寫死在多處）。
- 朋友比較改用同一套配對分數。
- 儲存距離選擇。

## 11. 風險

- **人數估計**：合菜會被算成更多人，每人金額偏低；一個人點兩份主餐會算成兩人；沒有正餐的發票不列入。
- **固定順序**：最像你、最不像你只取順序中的第一個，不一定是差異最大的一項。
- **行政區層級**：不是實際距離，同一區的兩端可能比隔壁區更遠。
- **示範版**：看不到距離選項，要用私人報告或修改示範資料才看得到。
