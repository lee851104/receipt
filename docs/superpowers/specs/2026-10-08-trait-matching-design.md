# 配對頁改用品味特質：設計規格

- 日期：2026-10-08
- 分支：`feature/taste-traits`
- 範圍：第二段（配對頁與神經網路連線圖）拆成三輪，這是第①輪：配對頁改用品味特質，並移除舊配對程式。第②輪是神經網路連線圖、圖的切換與大字分數；第③輪是品味連結新版與匯出。三輪都完成後才合併。
- 依據：[`2026-10-07-taste-traits-design.md`](2026-10-07-taste-traits-design.md) §7、[`../handoffs/2026-10-08-taste-traits-stage1.md`](../handoffs/2026-10-08-taste-traits-stage1.md)
- 取代：[`2026-10-07-tags-matching-design.md`](2026-10-07-tags-matching-design.md) 與 [`2026-10-07-match-simplify-design.md`](2026-10-07-match-simplify-design.md) 的配對分數與配對頁。

## 目標

「找到同好」改用第一段的品味特質相似度排序，看得出誰和你合拍、誰和你相反，以及原因。舊的品類、品牌、葷素、檔次加權公式，以及它的程式、設定與測試，全部移除。

## 已確認的決策

| 項目 | 決定 |
|---|---|
| 拆分 | 第二段分三輪，各自走規格 → 計畫 → 實作，都在同一分支 |
| 距離篩選 | 保留成次要篩選：先依相似度挑人，再依距離縮小 |
| 合拍名單 | 相似度 +30% 以上，最多 5 人 |
| 負相關 | 開關「也看看跟你相反的人」，預設關閉；打開後列出 −30% 以下的人，最多 5 人 |
| 卡片 | 分數，加上「最像你」「最不像你」各一項特質 |
| 你的品味特質 | 跟一般人比最突出的 3 項，加上有紀錄的程度型習慣 |
| 計算位置 | Python 算好向量並嵌入；分數與名單由瀏覽器用 `trait-similarity.js` 計算，第③輪匯入連結時沿用同一條路 |
| 點卡片 | 這一輪仍打開現有的類別連線圖，只把大字分數換成品味相似度 |

## 1. 資料

### 配對頁資料

`build.py` 產生 `matchReportData`，取代舊的 `build_matches` 輸出：

```text
{
  "isDemo": true,
  "population": 40,
  "personaMonths": ["2026-03", "2026-04"],
  "model":    similarity_model(traits.json) 的輸出：18 格的 id、kind、weight，以及 shrink、min_shared_two_sided
  "traits":   18 筆，順序同 model.cells：
              兩端型 {"id", "name", "kind": "two_sided", "ends": [左端, 右端]}
              程度型 {"id", "name", "kind": "level", "habit": 短詞}
  "settings": {"min_score": 0.3, "top": 5, "min_items": 20}
  "me":       {"vector": 18 格相對向量或 null, "months": [...], "areas": [生活圈行政區], "counts": 10 類筆數}
  "people":   40 筆，順序同 build_personas：
              {"name", "vector": 18 格相對向量, "distance": 0～3, "place": 第一個生活圈行政區或 null, "counts": 10 類筆數}
}
```

- **相對向量**：減去 40 位虛構用戶的平均，見第一段 §2「一般人的位置」。數字保留完整精度、不四捨五入，瀏覽器算出的分數因此和 Python 一致。
- **共用函式**：`traits.py` 新增一個函式。它從一群人（40 位虛構用戶）算出中間點，回傳中間點，以及這群人加上額外名單（例如朋友）的原始向量與相對向量。`build.py` 與 `tests/test_personas.py` 都改用它，不再各寫一份。名字重複時拋出 `ValueError`，不讓同名的人互相覆蓋。
- **settings**：`min_score` 與 `top` 放在 `configs/traits.json` 新增的 `"match": {"min_score": 0.3, "top": 5}`。`min_items` 取自既有的 `min_items`（20），只用於資料不足的說明文字。負相關門檻為 `−min_score`。
- **程度型短詞**：`configs/traits.json` 的 8 個程度型各加 `"habit"`：運動投入 → 運動、自己開車騎車 → 開車騎車、生活質感小物 → 生活小物、3C 投入 → 3C、娛樂體驗 → 娛樂、有養寵物（貓）→ 養貓、有養寵物（狗）→ 養狗、小酌 → 小酌。
- **10 類筆數**：只給點進連線頁時的類別圖用。規則和現在一樣：金額大於 0、分類已確認，同一張發票的同一品名只算一次。由 `signals.py` 的新函式計算，不依賴 `tags.py`。
- **私人版**：「我」用私人資料計算，資料不足時 `vector` 為 `null`；40 人與中間點不變。「我」的生活圈只出現在私人報告裡，和現在一樣。

### 生活圈與距離（`places.py`）

- **生活圈**：與第一段 `home_cities` 同一規則。在有行政區的付費發票中，取占 20% 以上的行政區，最多兩個，非實體賣方不計；依發票數排序，同數時依名稱。`signals.py` 把這段規則抽成回傳行政區的函式，`home_cities` 改成取這些行政區的縣市，行為不變。
- **距離**：取兩人生活圈中最接近的一組。同一行政區為 0，同縣市為 1，同地區為 2，其他為 3；任一方沒有生活圈時為 3。
- **地區對照表**：從 `configs/tags.json` 搬到新的 `configs/regions.json`，內容不變（北部、中部、南部、東部、離島）。
- 距離由 Python 先算好放進 `people[].distance`，瀏覽器不需要地區表。

## 2. 配對頁

### 名單

`match-filter.js` 改寫成純函式，用 `TraitSimilarity.compare` 算出「我」和每個人的分數與每格貢獻；無法比較的人略過。

1. **合拍**：分數 ≥ `min_score` 的人。**相反**（開關打開時）：分數 ≤ `−min_score` 的人。
2. **距離篩選**：不限（預設）、同一區（距離 0）、同縣市（≤ 1）、同地區（≤ 2）。
3. **排序**：用未四捨五入的分數排序，合拍由高到低、相反由低到高；分數完全相同時依名字排。各取前 `top` 人。距離篩選在取前 5 人之前套用。

分數顯示用 `TraitSimilarity.percent`：正數加「+」，負數用「−」（U+2212），0 顯示「0%」。

### 畫面

由上到下：

1. 「← 返回消費洞察」、標題「從消費習慣，找到合拍的人。」與說明：配對對象是 40 位虛構示範用戶，「我」也是虛構示範資料，點一個人看你們的連線圖。
2. **你的品味特質**（直接顯示，不收合）：
   - 「跟一般人比：」列出 |值| ≥ 0.2 的兩端型中最大的 3 個，寫成「偏 + 那一端」。同值時依特質順序。
   - 「也有」列出值大於 0 的程度型，用短詞串成「也有運動、生活小物、3C 的紀錄」。
   - 兩者都沒有時寫「跟一般人差不多」。
   - 資料不足時寫「資料還不夠，看不出品味特質」。
3. **和你最合拍的人**：狀態文字、距離選項、卡片清單。距離選項旁顯示「你的生活圈：…」；看不出生活圈時，只能選「不限」，其他選項停用。
4. **開關**「也看看跟你相反的人」。打開後顯示「和你最不一樣的人」：狀態文字與卡片清單，距離篩選與合拍名單共用同一個選擇。
5. **怎麼算的？**（收合）。

### 卡片

`<button>` 卡片，內容依序是名字、分數（正負用不同顏色）、主要行政區（`place`，沒有時不顯示），以及兩行：

- **最像你**：貢獻最大且大於 0 的格。
- **最不像你**：貢獻最小且小於 0 的格。
- 沒有符合的格時，那一行不顯示。

文字規則（稱呼一律用「對方」）：

| 情況 | 文字 |
|---|---|
| 兩端型、兩人同方向 | 都偏{同一端}，例：都偏香甜 |
| 兩端型、兩人反方向 | 你偏{我的端}，對方偏{對方的端}，例：你偏常出遊，對方偏待在生活圈 |
| 程度型（只會加分） | 都有{短詞}的紀錄，例：都有養貓的紀錄 |

### 狀態文字

| 情況 | 文字 |
|---|---|
| 「我」資料不足 | 你的資料還不夠（有效品項少於 20 筆），先累積更多發票，再來找同好。 |
| 有人達門檻 | N 位品味相似度 +30% 以上。超過 5 位時加上「，顯示前 5 位」 |
| 沒人達門檻 | 目前沒有品味夠相似的人（+30% 以上）。 |
| 距離篩選後沒人 | 這個距離內沒有品味相似度 +30% 以上的人，試試放寬距離。 |
| 相反：有人 | N 位品味相似度 −30% 以下。超過 5 位時加上「，顯示前 5 位」 |
| 相反：沒人 | 目前沒有和你明顯相反的人（−30% 以下）。 |
| 相反：距離篩選後沒人 | 這個距離內沒有品味相似度 −30% 以下的人，試試放寬距離。 |

- N 是套用距離篩選後的人數。完全沒有人達門檻時，顯示「沒人達門檻」，與距離選擇無關。有人達門檻、但選定距離內沒有時，才顯示「距離篩選後沒人」。
- 「我」資料不足時，只顯示那一句，不顯示距離選項、開關與卡片。
- 文字中的 20、+30%、5 都由 `settings` 產生，不寫死。

### 怎麼算的？

1. 每個人的發票先整理成 17 項品味特質（18 格），例如「省錢 ↔ 享受」「清爽 ↔ 香甜」「運動投入」。兩端型特質減去 40 位虛構用戶的平均，表示跟一般人比偏哪一邊。
2. 兩個人的相似度用餘弦相似度計算，範圍 −100%～+100%，負數表示品味方向相反。特質都很淡的人，分數會往 0 收斂。
3. 相似度 +30% 以上才列為合拍，最多 5 位。打開「也看看跟你相反的人」，會另外列出 −30% 以下的人。
4. 距離看生活圈：占你發票 20% 以上的行政區，最多兩個。同一區、同縣市、同地區依兩人生活圈最接近的一組判斷。
5. 「最像你」「最不像你」是對分數加分最多與扣分最多的特質。
6. 此配對頁只用行政區與特質分數，不顯示店名、品名、日期或金額。私人版加上原有的「這份私人報告的其他頁面仍有完整交易明細…」。最後一句「配對對象皆為虛構示範用戶。」不變。

## 3. 點卡片：連線頁（過渡）

合拍與相反的卡片都可以點，照樣打開現有的連線頁（類別圖不變），只改三處：

- `pair.score` 是品味相似度的整數百分比，可以是負數。`TasteProfile.fromPair` 原本只接受 0～100，改成接受 −100～+100 的整數；超出範圍或不是整數時，照舊退回配對清單。
- 大字標籤「配對分數」改成「品味相似度」，數字帶正負號。
- 下方小字「消費類型相似度 N%（下圖）」暫時保留，說明下面那張是類別圖。第②輪換成新連線圖與切換時再拿掉。

「← 返回配對清單」不變。配對頁不重新載入，開關與距離選擇因此會保留。朋友比較頁（小安 × 小宇）這一輪不動。

## 7. 風險

- **門檻來自虛構資料**：+30% 與 5 人是依示範分布選的。真實資料的分布可能很不一樣，到時要重新校準。
- **沒有生活圈的人**：距離為 3，只會在「不限」時出現。這是刻意的，看不出住哪裡就不假裝很近。
- **頁面變大**：40 人的完整向量約增加 15 KB，報告仍是單一 HTML 檔。
- **私人資料**：私人報告會嵌入「我」的向量與生活圈。私人報告本來就有完整交易明細，而且不進 Git。
- **加總順序**：Python 3.12 與瀏覽器的加總差在 4.4e-16 以內，示範資料的百分比完全相同。名單由瀏覽器算，Python 只印分布，兩邊不會同時顯示同一組分數。
