# 四項指標的計分方式

這是 16 個可同時成立的屬性，含 13 個布林、甜度、活動類型、貓狗種類；不是互斥的 16 選 1 分類。本輪只對 attributes 計分，basic 的 7 個旗標不混入主成績。舊 RESULTS.md 第一輪的整筆一致包含 basic，不能直接與本輪的整筆一致比較。

- **Accuracy（欄位準確率）**：完全答對的屬性欄位數／有參考答案的欄位數。不是整張發票全部正確的比例，也不是 micro F1。
- **Precision（精確率）**：TP／(TP+FP)，模型判定有某屬性時，有多少符合參考答案。
- **Recall（召回率）**：TP／(TP+FN)，參考答案中的正例有多少被找出。
- **F1**：2TP／(2TP+FP+FN)，平衡 Precision 與 Recall。未產生正例或分母為零時採 0，不給虛假的滿分。

主表 P/R/F1 採 micro：先加總各屬性的 TP、FP、FN。另報每個屬性的 F1，以及有正例屬性的 F1 算術平均（macro_f1_supported）；沒有正例的屬性標為未驗證。選型依 macro F1，避免少數常見屬性掩蓋其他屬性。

## 型別與未知值

- 布林 true 是正標籤，false 是負例。參考答案為 null 的布林欄位不評分；模型在這些位置的輸出不算對或錯。
- 模型布林 null 或缺失整筆不是正確的 false；仍占 Accuracy 分母。對真實正例則記 FN。
- sugar=0 是「無糖」正標籤，不是 false。甜度、fun、species 每個具體值視為一種標籤；答錯子類別同時計一個 FP 與 FN。
- enum 的 null 表示沒有指定可輸出的子類別，包括不適用與資訊不足；在本契約中不是具體正標籤。此分數只衡量能否遵守「有明示才輸出」的標註政策，不能證明未知商品的實際甜度或種類。
- `abstained_fields` 只統計有參考答案欄位中的「缺失或布林 null」，不包含合法的 enum null。
- 失敗批次保留在分母；正例漏答算 FN，不丟棄不利樣本。另列有效輸出組數、失敗批次、整筆 16 屬性全對數。

## 證據限制

真實集是三月 28 組商品，由助理標註初稿，尚未經使用者複核，且曾用於提示調整。補充集是助理構造的 54 筆情境，已在本輪推論前凍結，另由未看模型輸出的審查者依規格檢查標籤。兩者都不是經使用者確認的獨立真實測試集。

補充集每個屬性有 2–6 個正例，合計 45 個正標籤；864 個欄位中，大多仍是負例。全部答 false/null 的 Accuracy 已有 94.79%，F1 卻是 0。不可只根據 Accuracy 宣稱可部署，也不可將補充集結果當作真實世界的泛化成績。

程式：metrics.py；手算算例與完整性檢查：test_metrics.py；報表重算：followup_report.py。批次比較會拒絕來源／提示 SHA 不同、未跑完或 ID 未完整覆蓋的資料。

## 模型加規則的獨立成績

bulk_rule.py 只在數量 >=3、數字+入、整箱、箱裝、家庭號或量販包有明確證據時將 bulk 改為 true。它不查看參考答案，也不補出模型失敗的整筆預測。沒有證據時保留模型原值，其他欄位不變；原始預測不覆寫，改動列在 overrides。

此規則在 Qwen3 開跑前固定，源自既有專案的數量／包裝定義。純模型仍按原始分數比較；`with_bulk_rule` 和 CSV 的 `+bulk-rule` 列屬於「模型加規則」系統分數，不能當成模型本身的成績。兩組都使用同一份凍結參考答案。

最後發現模型在真實品名未明示甜度時仍猜數字，因此新增 sugar_guard.py：缺乏明確甜度詞時將 sugar 保留 null。這只驗證文字證據是否存在，沒有估算營養，也不保證商品種類或甜度數值正確。它不增加正標籤、不補失敗項目、不讀參考答案。

甜度 guard 是看過錯誤後新增，`with_policy_guards` / `+policy-guards` 必須稱為「修正後開發資料回測」，不能當獨立 holdout 成績。原始模型與 bulk-only 成績均保留，不修改原始回答、參考答案、模型權重或提示。
